CURRENT BEHAVIOR

Alive-looking process, incomplete evidence

  • Thousands of markets continuously polled; trade pairs can still age out.
  • Critical discovery failure marks red but does not terminate the paper run.
  • Pair approvals persist; evaluation rejection reasons do not.
  • Dashboard and heartbeat can suggest activity after trading work has stopped.
REQUIRED BEHAVIOR

A small, provable trading funnel

  • Approved pair IDs own a dedicated snapshot fetch with a bounded deadline.
  • Every cycle persists a terminal reason and freshness/edge evidence.
  • Discovery and scanner health determine readiness and run status truthfully.
  • One manually reviewed current pair proves recall before any long paper claim.

Shortest credible recovery sequence

Make the funnel observable, then prove each gate

1

Create the end-to-end acceptance harness

Use one manually reviewed current equivalent pair. The unattended command must prove matcher recall, paired snapshot freshness, economics, a paper ledger event, and explicit no-mutation behavior. This becomes the red/green production-candidate gate.

2

Deepen the market-data boundary

Replace “read whatever is in the global cache” with a pair-snapshot interface that returns both venue books, fetch timestamps, identity, and freshness as one result. Supervise its lifecycle and refuse to report scanner health without it.

3

Persist the complete decision funnel

Store compact per-cycle counters and reason-coded rejections in SQLite. Keep raw DEBUG request success out of production logs. A zero-trade run must say exactly how many pairs were fresh, how many had positive gross edge, and how many cleared costs.

4

Pass a production-shaped paper gate

Run on live public books with the manually approved pair and conservative shadow execution. Require sustained fresh evaluation and at least one deterministic fixture-backed paper lifecycle; then observe current markets without forcing an opportunity.

5

Exercise operations before money

Deploy the pinned commit with execution disabled. Prove restart, backup/restore, TLS operator access, alert receipt, clock discipline, and Kalshi private-stream disconnect/reconciliation.

6

Authorize one minimum-size live canary

Exactly one reviewed pair, one two-leg plan, staffed response, smallest venue-valid size, immediate panic afterward, and complete fee/fill/residual evidence. No automatic retry and no promotion on a discrepancy.
