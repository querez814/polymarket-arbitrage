2 Current State: What Works

Mature & Well-Tested

  • Bundle Arbitrage Engine — buys YES+NO when total_ask < 1.0, sells when total_bid > 1.0; fee-aware, duration tracking, cooldown logic.
  • Market Making Engine — places inside-spread limit orders, one-sided MM support, tick-size-aware.
  • Polymarket Global Client — Gamma API markets, CLOB orderbooks (real & simulated), batch polling with rate limiting for 5,000+ markets.
  • Risk Manager — kill switch, per-market/global/strategy exposure limits, daily loss & drawdown triggers.
  • Portfolio Tracker — FIFO cost basis, realized+unrealized PnL, win/loss stats.
  • Paper Trading Ledger — SQLite store with full lifecycle events (placed→filled/cancelled/expired), decision linking.
  • Web Dashboard — FastAPI + WebSocket SPA showing markets, opportunities, orders, portfolio, risk, decisions, timing stats.
  • Configuration System — YAML with env var overrides, 3 risk presets (conservative/balanced/aggressive), extensive validation.
  • Backtesting — single-platform simulation with random-walk orderbooks; cross-platform historical replay.
  • Test Suite — 18 files covering arb engine, portfolio, risk, execution, cross-platform replay, config, paper store, Kalshi auth, US parsing.

Incomplete or Untested

  • Zero Live Orders — neither Polymarket Global, Polymarket US, nor Kalshi have ever placed a real order.
  • Kalshi Can't Trade — client fetches markets & orderbooks but has no order placement method. Missing: place_order(), cancel_order().
  • Cross-Platform Execution Stops at Detection — CrossPlatformArbEngine.check_arbitrage() finds opportunities and writes to DecisionJournal + Dashboard, but ExecutionEngine never consumes cross-platform signals.
  • Polymarket US Untested Live — US client wraps SDK and supports order placement, but never tested against the live exchange with real funds.
  • No Wallet/Funding Setup — Polygon USDC wallet, Kalshi deposit, Ed25519 API keys — all config templated but not set up.
  • ClobTradingBridge Untested — wraps py_clob_client_v2 for live CLOB trading but has never placed an order against the live exchange.
  • No Monitoring Alerts — logs exist but no Telegram/Discord/email notifications for trades, errors, or kill-switch events.
  • No Deployment Story — no Dockerfile, no systemd/launchd, no healthcheck endpoint, no restart-on-crash.

6 Key Risks & Mitigations

Risk Impact Mitigation
One-sided fill on cross-platform
Buy fills on Poly, but sell doesn't fill on Kalshi (or vice versa)		 $Loss Use limit orders only. Set aggressive timeouts (30s). Auto-cancel unfilled leg and close open position at market. Implement "cross-platform pair" tracking that prevents orphaned legs.
Derived Kalshi asks are wrong
Kalshi only returns bids; asks derived mathematically may not reflect real liquidity		 $Loss Apply 2% safety discount to derived asks. Only trade when depth > $100 on both sides. Start with smallest orders ($5).
Market matching false positives
Text similarity matching pairs wrong markets (e.g., "Will Trump win" vs "Trump win margin")		 $Loss Require manual approval of matched pairs before trading. Add date matching and outcome-type matching (binary vs scalar).
Bot runs away (bug causes rapid orders)
Software defect places dozens of orders rapidly, draining account		 Account drain G5 safety limits (max 3 open, max 5/day). Kill switch on daily loss $10. Manual kill switch button. Cooldown between trades (60s min).
Exchange API outage mid-trade
Polymarket or Kalshi API goes down while order is open		 Stuck position G7 crash recovery: on restart, fetch open orders and positions from exchange. Auto-cancel stale orders older than 5min.
Polygon gas spike
Gas costs eat all profit or make transactions fail		 Unprofitable Include gas in edge calculation (already done in ArbEngine). Set max gas per tx. Monitor gas before placing orders.

8 Open Questions for PM Decision

Q1: Which venue first?

Polymarket Global (more mature client, bundle arb well-tested) vs Polymarket US (CFTC-regulated, simpler setup, different fees)?

Recommendation: Global

Q2: Solo or cross-platform only?

Start with single-platform bundle arb (simpler, already well-tested) then add cross-platform, or go straight to cross-platform?

Recommendation: Solo first

Q3: Order sizing?

Start at $5 minimum orders (very small edge) or $2 (even smaller, more trades)? Larger = fewer trades but cleaner data.

Recommendation: $2-5

Q4: Run on laptop or cloud?

Phase 1-2 can run on your Mac. Phase 3+ may need cloud for reliability. Cheapest VPS is ~$5/month.

Recommendation: Laptop first
